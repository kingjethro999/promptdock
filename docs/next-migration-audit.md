## Asset and styling check

The four brand PNGs, favicon, and two social images in `public/` match the preserved files in `oldui/` byte for byte. Next.js serves them at `/assets/brands/*`, `/favicon.svg`, and `/social-card*.png`. The old UI host also serves its brand PNG paths. The landing page uses `next/image` for fixed brand assets. CSS for the Next-only UI is grouped under `src/styles/next/`; true global rules are in `src/app/globals.css`.

The main site keeps its shared base rules in `src/styles/shared/`, Next-only adjustments in `src/styles/next/`, and global primitives in `src/app/globals.css`. The port 3000 source and its own stylesheet copies now live entirely in `oldui/`, including the old 4,000-line browser script. No Next.js route imports that script. The Next browser UI is split across App Router routes, components, hooks, stores, and utilities. Shared legacy selectors still need gradual deduplication, but they no longer sit as root-level `src/*.css` files.

## Shared backend

The old static host now lives in `oldui/server.js`. It serves only the preserved pages and sends `/api/*` and `/feed.xml` to `src/backend.js`. Next.js uses the same backend implementation through `src/lib/server/node-api-adapter.ts`. Authentication, encrypted keys, referrals, rate limits, prompt storage, and AI behavior have one implementation. The backend still uses Node request and response streams internally; it is not duplicated as separate Web-native route handlers. `vercel.json`, `npm start`, and `npm run dev` use Next.js. This is a code-level deployment configuration change, not a live deployment.
